# 프로젝트 개요

## 왜 만드는가

고령 사용자가 여러 체성분 수치를 직접 해석하지 않아도 최근 측정값과 안전 상태를 확인하고, 진동 설정이 어떻게 계산됐는지 이해한 뒤 시연 장치를 조작할 수 있게 한다.

## 올바른 동작

- 로그인한 참여자와 같은 FITRUS 기기의 유효한 최근 측정값 4건만 사용한다.
- 원본, 평균, 계산 기준과 결과를 화면에 구분해 표시한다.
- 공급사 `골격근량` 정의가 `ASM` 또는 `SMM`으로 확인된 경우에만 해당 경로를 사용한다. `UNKNOWN`을 사용자가 임의 선택해 해석하지 않는다.
- 통증, 어지럼, 사용 보류, 데이터 오류에서는 전송을 차단한다.
- 앱 결과와 서버 재계산이 다르면 세션을 만들지 않는다.
- 실제 장비 명세와 교정값이 없으므로 물리 출력은 항상 비활성화한다.
- `pilot-0.7.0`은 근육지수 연구 구간별 Mock 후보를 표시하며 나이·성별·체지방 강도 곱셈 보정은 사용하지 않는다.

## 책임

| 구성요소 | 책임 |
|---|---|
| `mobile-app` | 입력·통계·연구 후보 표시, 확인된 정의 고정, 문진과 Mock 시뮬레이터 조작 |
| `backend-api` | 비밀키 보호, 인증, 데이터 소유권, 추천 재계산, 시연 세션 감사 기록, `SqlDatabase` 저장소 포트 |
| `shared-contracts` | 앱과 서버의 HTTP·데이터 계약 및 공통 검증 fixture |
| `deployment/aws` | AWS 담당자에게 필요한 환경변수·DB·안전 기본값 인계 |

## 완료 기준

Mock 환경에서 `로그인 → 4건 검증·통계 → 확인된 ASM/SMM 층화 → 안전 문진 → 시뮬레이터 전송 → 시작 → 중지 → 피드백` 흐름과 오류·중복 방지 테스트가 통과하면 시연 버전 완료로 본다. 실제 API와 하드웨어는 각각의 공식 계약과 교정 검증 후 별도 완료 판정을 한다.

`pilot-0.7.0` 로컬 검증에서 백엔드 typecheck와 Vitest 43/43, Flutter format·analyze와 전체 테스트 38/38이 통과했다. debug APK는 로컬에서 반복 생성하지 않고 최신 main의 GitHub Actions 결과로 확인한다. 이 결과는 임상 효과나 실장비 안전을 의미하지 않는다.
