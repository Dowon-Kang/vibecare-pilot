# 프로젝트 개요

## 왜 만드는가

고령 사용자가 여러 체성분 수치를 직접 해석하지 않아도 최근 측정값과 안전 상태를 확인하고, 진동 설정이 어떻게 계산됐는지 이해한 뒤 시연 장치를 조작할 수 있게 한다.

## 올바른 동작

- 로그인한 참여자와 같은 FITRUS 기기의 유효한 최근 측정값 4건만 사용한다.
- 원본, 평균, 계산 기준과 결과를 화면에 구분해 표시한다.
- 공급사 `골격근량` 정의가 불명확하므로 ASM과 SMM 결과를 함께 계산하고 선택을 기록한다.
- 통증, 어지럼, 사용 보류, 데이터 오류에서는 전송을 차단한다.
- 앱 결과와 서버 재계산이 다르면 세션을 만들지 않는다.
- 실제 장비 명세와 교정값이 없으므로 물리 출력은 항상 비활성화한다.
- `pilot-0.6.0`은 근육지수 등급별 Mock preset을 선택하며 나이·성별·체지방 강도 곱셈 보정은 사용하지 않는다.

## 책임

| 구성요소 | 책임 |
|---|---|
| `mobile-app` | 입력·평균·추천 표시, 기준 선택, 문진과 Mock 장치 조작 |
| `backend-api` | 비밀키 보호, 인증, 데이터 소유권, 추천 재계산, 시연 세션 감사 기록, `SqlDatabase` 저장소 포트 |
| `shared-contracts` | 앱과 서버의 HTTP·데이터 계약 및 공통 검증 fixture |
| `deployment/aws` | AWS 담당자에게 필요한 환경변수·DB·안전 기본값 인계 |

## 완료 기준

Mock 환경에서 `로그인 → 4건 평균 → ASM/SMM 선택 → 안전 문진 → 전송 → 시작 → 중지 → 피드백` 흐름과 오류·중복 방지 테스트가 통과하면 시연 버전 완료로 본다. 실제 API와 하드웨어는 각각의 공식 계약과 교정 검증 후 별도 완료 판정을 한다.

마지막 검증 기준은 커밋 `13a16c0`과 [GitHub Actions run 34443151436](https://github.com/Dowon-Kang/vibecare-pilot/actions/runs/34443151436)이다. 백엔드 typecheck와 Vitest 56/56, Flutter format·analyze·전체 테스트·debug APK 빌드가 통과했다. 이 결과는 임상 효과나 실장비 안전을 의미하지 않는다.
