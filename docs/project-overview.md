# 프로젝트 개요

## 실제 생활 돌보기 AI 계약 (2026-10-15, 전송 승인 후)

사용자는 앱 내 동의 후 골격근량·체중·체지방률과 선택한 생활 목표만 OpenAI API로 전송하는 실제 연결을 승인했다. 이름·이메일·계정/측정 식별자·원본 CSV·질환/문진 원문은 공급자에게 보내지 않는다. 기존 Hono PIN 연결 제안은 미구현 이력으로 보존하며 이번 운영 경로는 Flutter Supabase Auth → 같은 프로젝트의 인증된 Edge Function → OpenAI Responses API로 확정한다. 공개 샘플의 Gemini 연결은 아래 2026-10-15 합성 시연 계약에 따르며 실제 사용자 정보는 Gemini에 전송하지 않는다.

서버는 사용자 JWT를 Auth 서버에서 검증하고 기존 RLS로 본인 최신 측정만 읽는다. SMM 정의·kg·획득 방법/프로토콜·품질·유효 범위·30일 신선도가 확인되지 않거나 표시한 측정과 달라지면 요청을 차단한다. 비교 가능한 이력이 입증되지 않아 변화량과 건강 등급은 생성하지 않는다. 음식·활동 제한과 현재 통증/어지럼/의료진 보류 답변은 서버의 후보 제거에만 사용한다. 알 수 없음도 해당 개인 안내를 보류한다.

AI는 검토된 일반 음식·활동 후보와 해석 관점의 허용 ID만 선택하며 자유 진단·처방·열량·운동 강도·시간·횟수를 만들지 않는다. 화면은 측정값 이해 → 음식 후보 → 움직임 후보로 구성하고, 앱이 계산한 측정 사실과 AI 선택을 구분한다. 연구 등급은 입력하지 않는다. 전송 직전에 공급자·세 수치·목표·기본 남용 감시 보존 가능성을 표시하고 매 요청 동의를 받는다. store:false, 출력 상한·타임아웃·자동 재시도 없음, 계정당 UTC 하루 3회/전체 100회 원자적 한도를 적용한다. 실패도 외부 호출을 예약한 횟수에 포함해 반복 비용을 제한한다. 공급자 원문·문진·응답은 DB/로그에 저장하지 않고 사용자별 일자·횟수만 저장한다. 계정·측정·제한/목표 변경, 화면 종료 때 요청을 취소하고 응답을 폐기한다.

서버 API 키는 Supabase Secret에만 보관한다. 키·함수 배포·합성 데이터 실제 공급자 검증·Flutter 회귀/웹/APK/CI가 완료되어야 실제 연결 완료로 기록한다. 물리 출력 PROHIBITED / SIMULATOR_ONLY 및 기존 알고리즘·안전 차단은 유지한다.

## 측정 시작 발견성 개선 (2026-10-15)

홈의 첫 행동 카드는 측정 시작이며 예약·출석보다 앞에 배치한다. 48dp 이상 기본 버튼과 대비가 높은 색상으로 표시한다. 샘플은 기존 연구 흐름으로 연결하고, 실계정의 측정 시작은 측정 준비 안내를 연다. FITRUS 원격 측정 기능이 없는 현재 상태를 밝히고 연결된 기록 확인·예약·합성 시연을 선택하게 한다. 실제 기기 측정이 시작됐다고 표시하지 않는다.

## 모바일 화면 연결·배포 계약 (2026-10-15)

승인된 HTML 시안을 Flutter의 기존 기능에 연결한다. 기본 탐색은 측정 기록·홈·생활 돌보기·내 프로필이며 상단은 알림함이다. 홈의 측정 시작은 실제 FITRUS를 시작했다고 표시하지 않고 기존 샘플 연구 흐름 또는 연결된 측정 확인으로 이어진다. 출석·예약은 기존 저장소를 재사용하고 사용자 변경·로그아웃 시 이전 계정의 화면·응답을 숨긴다. 실제 계정에 측정이 없으면 빈 상태를 표시하며 합성 데이터를 채우지 않는다.

내 프로필에서 이 기기의 예약 알림 사용 여부·사전 알림 시간과 생활 안내 알림 시간을 설정한다. Android는 기존 로컬 알림 채널을 사용하고 웹은 앱이 열려 있는 동안에만 안내한다. OS 권한 상태·설정 오류를 성공으로 위장하지 않는다. 실제 서버 푸시·AI 전송·FITRUS 연결·물리 장치 실행은 이번 UI 배포로 추가하지 않는다. 기존 API·알고리즘·안전 차단·Mock/실제 데이터 구분을 유지한다. 배포는 기존 GitHub Pages와 내부 검증용 APK 흐름을 사용한다.

## AI 연결·추천 사용성 개선 계약 (2026-10-06)

사용자는 실제 AI 연결과 음식·운동 추천 UI 개선을 요청했다. **아래는 연결 제안이며 미구현이다.** 실제 OpenAI 호출 코드 추가는 자동 승인 검토에서 구체적 건강정보 payload/목적지에 대한 사용자 승인 부재로 거절되어 승인 질문을 제시했다. 키·운영 API 주소도 확인되지 않았다. 기존 PIN 인증 Backend API에 OpenAI Responses API를 연결하는 안을 제안한다. 기본 모델 후보는 `gpt-6-luna`; 사용자 서버 키·과금 설정은 필수다. 무료 제공을 보장하지 않는다. Supabase 로그인과 PIN 인증을 임의로 연결하지 않으며 공개 Pages 샘플은 외부 AI를 호출하지 않는다.

AI는 서버가 허용한 생활관리 후보 ID와 해석 관점만 선택한다. 수치 요약·비교는 서버 계산이고 제목·실천 행동·추천 이유·주의사항·공식 출처는 검토된 카탈로그 문구다. 모델이 질병 진단·건강 점수·영양 섭취량·운동 강도/시간/횟수를 만들어내지 않는다. 식사/활동 제한이 미확인 또는 존재하면 해당 개인 후보를 보류한다. 문진 미완료·증상·기존 피드백 보류는 운동 후보보다 우선한다. 일반 교육 후보의 실제 개인 적합성을 입증하는 기능은 아니다.

제안은 매 요청에 전송 안내와 명시적 동의를 받으며 식사 제한 여부·활동 제한 여부·관심 목표를 세션 메모리에서 다루는 것이다. 공급자에는 식별자·연락처·원문 건강정보·연구 등급 없이 검증된 체성분 세 값, 비교 가능한 변화와 목표만 전송한다. 제한/문진 답변은 공급자에게 보내지 않고 서버에서 후보 보류 판단에만 쓴다. 공개 카탈로그를 모델이 선택한 뒤 서버가 보류 규칙을 적용해 해당 후보를 제거한다. DB에는 응답·문진 내용을 저장하지 않고 일자별 요청 횟수만 저장하는 안이다. 실제 측정 데이터 사용은 운영자의 별도 허용 설정도 필요하다. `store:false`는 공급자의 모든 보존을 없애는 옵션이 아니며 기본 남용 감시 보존을 사용자에게 알린다. 모두 아직 미구현인 후속 연결 조건이다.

관찰 가능한 완료 기준: 연결/샘플·대기·실패/재시도·요청 한도·안전 보류를 구분, 동일 측정과 소유자에만 응답 표시, 상태 변경/화면 종료 시 요청 취소·늦은 응답 폐기, 320px/큰 글자에서도 세 가지 질문과 카드 조작 가능. 실제 공급자 호출 성공은 키가 준비된 후 합성 데이터로 확인해야 한다.

## 결과 화면의 AI 건강관리 안내 준비 (2026-10-06)

사용자는 결과 화면의 AI 음식·운동 추천과 건강상태 분석을 요청했다. 실제 AI 공급자·서버 키·외부 전송 계약은 현재 없다. 우선 결과 화면 안에 측정값의 사실 해석, 일반 음식 후보, 운동 안내의 미리보기 구조를 구현한다. 준비된 예시를 AI 생성 결과라고 표시하지 않으며 `AI 미연결`을 펼치기 전부터 표시한다. 측정 수치·직전 비교는 앱 계산으로 구분하고 전체 건강 점수·질병 판정·연구 등급 기반 처방을 만들지 않는다. 음식은 알레르기·질환별 식사 제한이 미확인임을 표시하고 일반 식품군 예시만 제시한다. 운동 안내는 당일 문진 미완료·통증·어지럼·사용 보류·측정 검토 시 보류한다. 문진 통과도 개인 운동의 안전성이나 허가를 증명하지 않는다.

실제 AI 단계는 서버를 통해서만 연결한다. 사용 목적·전송 항목·수신 AI 공급자·보존 여부를 밝힌 동의, 사용자 소유권 검증, 응답 형식/근거 검증, 타임아웃·재시도·취소·계정/측정 변경 시 응답 폐기, 비용 제한이 필요하다. 앱에 API 키를 넣거나 실제 측정·질환·복용약 정보를 동의 없이 외부로 전송하지 않는다. 사용자는 이번에 **결과 화면·샘플 응답 먼저 구현하고 검증**을 선택했다. 미리보기는 실제 모델 연결 완료로 간주하지 않는다.

## 2026-10-06 건강관리 1차 확장

대상은 기존 연구 참여자와 고령 사용자다. 측정 이해·예약·출석·연구 시연 흐름에 생활 습관 관리를 추가한다. 홈에서 사용자가 움직임·식사 구성·취침 준비 중 관심 습관을 직접 선택하고, 오늘의 실천/쉬기/취소를 기록하며 최근 7일을 돌아본다. 미기록은 실패나 미실천으로 판정하지 않는다. 건강 점수·체성분 변화 보상·연구 등급 기반 운동/영양 처방은 생성하지 않는다.

생활 기록은 사용자 입력이며 측정값·시연 피드백과 별도다. 1차 저장 위치는 이 브라우저/기기로 한정하고 로그인 계정과 샘플 저장 키를 분리한다. 서버 동기화·다른 기기 복구·담당자 공유는 제공하지 않는다. 저장 위치와 전체 삭제 행동을 화면에 표시한다. 최근 90일 기록만 저장하고 기록 삭제는 확인 후 해당 계정만 삭제한다. 저장 실패를 성공으로 표시하지 않으며 계정 변경/로그아웃 시 열린 화면의 기록을 숨기고 읽기·쓰기를 차단한다. 일반 건강 안내는 WHO/NHS의 출처·확인일을 표시하며 사용자별 강도·시간·열량·영양 섭취량을 자동 설정하지 않는다. 기존 알고리즘, API, 안전 차단, 실제 장치 실행 금지는 유지한다.

`pilot-0.9.1` Mock 시뮬레이션은 여성, 70세 이상, 체지방률이 설정 범위를 벗어난 경우에 각각 0.95를 적용한다. 해당하지 않는 범주의 계수는 1.00이다. 세 조건이 모두 해당하면 총계수는 0.857375이며, 선택 부위와 근육 등급의 기본 강도에만 곱한다. 시간과 주파수는 바꾸지 않는다. 이 값과 체지방 범위는 임상적으로 검증되지 않은 연구용 가정이며 실제 장치 전송은 계속 금지한다. 기존 `pilot-0.9.0` 기록은 그대로 보존한다.

>
> **Update trigger:** 사용자 문제, 핵심 흐름, 안전 제약 또는 완료 정의가 바뀔 때

## 올바른 동작

- 로그인한 참여자와 같은 FITRUS 기기의 유효한 최근 측정값 4건만 사용한다.
- 원본, 평균, 계산 기준과 결과를 화면에 구분해 표시한다.
- 공급사 `골격근량` 정의가 `ASM` 또는 `SMM`으로 확인된 경우에만 해당 경로를 사용한다. `UNKNOWN`을 사용자가 임의 선택해 해석하지 않는다.
- 통증, 어지럼, 사용 보류, 데이터 오류에서는 전송을 차단한다.
- 앱 결과와 서버 재계산이 다르면 세션을 만들지 않는다.
- 실제 장비 명세와 교정값이 없으므로 물리 출력은 항상 비활성화한다.
- `pilot-0.9.0`은 최신 API 골격근량을 키²로 보정한 근육지수 등급에 맞는 6개 신체 부위의 고정 시간·Hz·강도를 Mock 화면에 표시한다.
- 로그인 직후 프로필 아래에서 통증·어지럼·사용 보류와 연구용 시뮬레이션 주의사항을 먼저 확인한다.
- Mock 로그인 화면에서 낮음·중간·높음 골격근량 페르소나를 선택하면 나이·성별·키와 대표 골격근량 이력이 프로필 설문에 자동 입력된다.
- 프로필 설문의 나이와 키 카드를 누르면 직접 입력과 빠른 선택을 제공하는 편집 창이 열리고, 적용 즉시 골격근량 판정과 추천값을 다시 계산한다.
- 두 번째 골격근량 확인 화면은 최신 골격근량 판정과 직전 기록 비교에 더해, 같은 최신 측정 건의 체중·BMI·체지방률·체지방량·기초대사량·체수분·단백질·무기질·세포외수분비 상태를 함께 보여 준다.
- 상단 사람 아이콘은 전체 화면 `프로필과 측정`으로 이동한다. 이 화면은 `내 정보`와 `측정 기록`을 탭으로 분리한다. `내 정보`는 성별·나이·키를 우선하고 최신 측정의 핵심 상태만 요약한다. `측정 기록`은 최근 4회 평균과 골격근량·체지방·체중 중 한 항목을 선택하는 추세 그래프를 보여 주고, 그래프 아래에 네 기록의 정확한 값을 유지한다. 전체 측정 항목과 생체신호는 별도 상세 화면에서 확인한다.
- 다음 화면에서 DB에 저장된 최신 골격근량과 직전 기록의 변화를 보여 주고, 성별 근육지수 연구 경계를 `낮음·중간·높음`으로 표시한다.
- 장치 설정 흐름에서는 인체 부위의 기본 시간·주파수·강도와 현재 규칙의 적용 결과를 보여 준다. `pilot-0.9.0`은 추가 계수가 없고, 현재 `pilot-0.9.1`은 문서 상단의 연구용 계수를 Mock 강도에만 적용한다.
- 사용자가 현재 위치와 다음 행동을 예측하도록 `프로필 → 골격근량 → 장치 설정` 진행 상태, 행동 결과, 비활성 이유를 화면에 명시한다.
- 장치 설정에서는 선택한 부위와 현재 골격근량 판정에 실제 적용되는 시간·주파수·강도만 표시한다. 다른 등급의 값은 기본 화면에 함께 노출하지 않는다.
- 장치 화면은 동일 설정 카드를 중복 표시하지 않고 추천 카드 한 곳에서만 시간·주파수·강도를 보여 준다.
- 시뮬레이션을 중지하면 완료 안내를 먼저 보여 주고, 사용자가 `사용 후 평가 시작`을 선택한 뒤 강도·운동자각도·시간·주파수·통증·어지럼 질문을 한 번에 하나씩 답한다.

## 참여 관리 시연 기능 (2026-10-01)

GitHub Pages의 기본 진입점은 Supabase Auth 이메일 로그인이다. 로그인한 사용자는 본인 예약·출석을 저장하고 달력·참여 횟수로 확인한다. 관리자가 연결한 실제 측정 기록이 있으면 최신·직전 값의 상승분을 표시한다. 연결된 기록이 없으면 빈 상태를 설명한다. 합성 측정값과 추천 매핑은 별도의 샘플 시연 화면에 명확히 표시한다.

- 참여자는 날짜와 시간을 예약하고 당일 출석을 기록할 수 있다.
- 예약일이 지나도록 출석이 없으면 미참여로 표시하며 달력과 참여율로 현황을 확인한다.
- Android는 기기 로컬 알람으로 예약 알림을 표시하고, 웹 시연은 앱이 열려 있을 때 예약 시각에 표시한다.
- 측정 전 화면에서 동일 기기와 측정 방법의 직전 결과와 비교해 증가한 항목을 표시한다. 수치 증가는 임상적 개선으로 해석하지 않는다.
- 시연용 합성 측정의 시간은 실행 시각을 기준으로 생성하며 실제 측정의 유효성 검사는 유지한다.
## 주간 참여와 홈 안내 (2026-10-01)

- 참여자는 시작 날짜와 시간을 고른 뒤 1회 또는 매주 4·12·52주 예약한다. 동일한 날짜와 시간의 기존 예약은 중복 생성하지 않는다.
- 출석은 예약 당일에 직접 체크한다. 완료된 예약 중 출석 비율이 80% 이상이면 별을 표시하고, 출석한 날짜에도 별을 표시한다. 예정된 예약은 비율의 분모에 포함하지 않는다.
- 홈은 실행, 출석 체크, 공지·안내를 분리한다. 연결 모드의 공지는 운영자가 게시한 Supabase 공지와 예약 상태 안내를 함께 보여준다. 샘플 모드는 별도 로컬 기록으로 홈을 시연한다.
- 출석은 참가자의 자체 기록이며 현장 방문 인증을 뜻하지 않는다. 웹 알림은 페이지가 열려 있는 동안에만 표시한다.
가입 화면은 로그인 화면과 분리하고 이메일 형식·6자 이상 비밀번호·비밀번호 재입력을 확인한 뒤 Supabase Auth에 가입을 요청한다. 이메일 인증이 필요한 설정에서는 확인 링크를 누른 뒤 로그인하도록 안내한다. 이메일 발신 제한은 클라이언트에서 우회하지 않는다.

## 예약 알림 보충 동작 (2026-10-02)

웹에서 현재보다 늦은 예약은 시작 시각 전에는 알리지 않는다. 페이지가 열려 있는 동안 시작 시각이 지나면 당일에 한해 한 번 안내하며, 브라우저 타이머가 지연되어도 당일 복귀 시 안내한다. 페이지를 닫은 상태의 푸시 알림은 지원하지 않는다. 비기능 점검은 [예약 알림 점검](notification-nfr.md)에 기록한다.

## 예약 입력 기본값 (2026-10-02)

예약 날짜·시간 선택창은 현재보다 늦은 15분 단위 시각을 기본으로 보여준다. 당일에 남은 15분 단위 시각이 없으면 다음 날 오전 10시를 기본으로 보여준다. 이미 지난 시각을 직접 선택하면 예약을 저장하지 않고 다시 선택하는 방법을 안내한다. 추천 사용 보류 상태는 예약 시간과 별개의 안전 판단으로 유지한다.

## 상단 내비게이션 (2026-10-03)

이전 화면이 있는 주요 화면에는 왼쪽 뒤로가기 화살표를 표시한다. 오른쪽에는 세 줄 메뉴 버튼을 두고 홈에서는 시연 실행·예약과 출석·공지 안내로 이동한다. 로그인 홈 메뉴에는 새로고침과 로그아웃을 포함한다. 예약 화면 메뉴에서는 새 예약과 알림 안내를 열 수 있다. 이전 화면이 없는 첫 화면에는 동작하지 않는 뒤로가기 버튼을 표시하지 않는다.

## 웹 홈·예약 화면 품질 (2026-10-03)

홈과 예약 화면은 넓은 웹에서도 본문 폭을 제한하고 카드와 버튼 사이에 충분한 간격을 둔다. 작은 화면과 큰 글자에서도 주요 동작을 사용할 수 있어야 한다. 달력 날짜의 예약·출석·미참여 상태는 색상 외에 보조 기술용 텍스트로 전달한다. 예약 기록 로딩 실패는 오류와 재시도 동작을 보여준다. 시연 홈에서 웹 알림은 페이지가 열려 있을 때만 표시한다. 자동화 검증 범위와 미검증 사항은 [웹 홈·예약 화면 비기능 요구사항 점검](web-ux-nfr.md)에 기록한다.

## 사용 후 통증 응답과 다음 시연 (2026-10-03)

사용 후 설문에서 이전 시연 중 통증이 있었다고 답한 사실만으로 다음 연구용 시뮬레이션을 영구 차단하지 않는다. 다음 추천의 강도 상한을 기존 정책의 10% 낮추는 규칙으로 조정하고, 새 시뮬레이션을 준비하기 전에 지난 통증 보고와 낮아진 강도를 확인하는 안내창을 보여준다. 사용자는 안내를 취소할 수 있다. 지금 통증·어지럼이 있거나 전문가의 사용 보류 지시가 있는 경우의 사용 전 안전 차단은 유지한다. 이전 시연에서 어지럼이나 시간·주파수의 심한 불편을 보고한 경우에는 기존 검토 보류를 유지한다. 이는 Mock/서버 시뮬레이터의 UX 정책이며 물리 장치 사용 허가나 임상적으로 검증된 강도 처방이 아니다.

## 예약·출석 탐색 UX (2026-10-03)

예약은 날짜·시간·반복 횟수를 한 화면에서 수정하고, 저장 전에 첫 날짜·마지막 날짜·총 횟수·이미 예약된 중복 횟수를 확인한다. 반복 항목을 고르는 것만으로 예약이 저장되지 않는다. 저장 또는 뒤로 가기를 명시적으로 선택한다. 출석 화면은 현재 달 일정을 기본으로 보여 주고 달력 날짜를 누르면 그날 예약과 출석 상태로 목록을 좁힌다. 다른 달로 이동하면 선택 날짜를 초기화한다. 주요 기능별 외부 앱 비교와 검증 기준은 [웹 주요 기능 UX 비교](ux-flow-comparison-2026-10-03.md)를 따른다.

마지막 날짜와 새 예약 수는 저장 버튼 바로 위에도 고정해 스크롤하지 않아도 확인할 수 있게 한다.


### 웹 모바일 프레임 (2026-10-15 추가)

넓은 웹 화면에서는 휴대폰 베젤 안에 실제 Flutter 앱을 표시한다. 폭 480px 이하 브라우저와 Android 앱에서는 장식 베젤 없이 화면 전체를 쓴다. 웹 프레임은 Flutter 공식 hostElement 임베딩 방식으로 실제 뷰포트 크기를 전달한다. 시안 설정·가짜 상태바 데이터는 기능으로 노출하지 않으며 로딩 실패 시 재시도할 수 있다.


## 2026-10-15 Gemini 합성 시연 계약

무료 Gemini 키는 샘플 생활 돌보기에서만 사용한다. 앱의 매 요청 동의 뒤 서버가 고정 합성 골격근량22kg/체중60kg/체지방률27%/식사 구성 목표만 전송한다. 실제 계정·측정·프로필·문진·CSV를 읽거나 Gemini에 보내지 않는다. 샘플용 공개 API는 앱 공개키를 확인하고 임의 필드를 거절한다. 공용 UTC 하루20회·분당3회 원자적 한도를 공급자 호출 전에 예약하고 실패도 횟수에 포함한다. 샘플 답변에는 Gemini·합성 시연임을 표시하며 실제 사용자에게 적용하는 처방이 아니다. 실제 측정 경로의 OpenAI 인증·동의·검증은 유지한다.

## 합성 데이터 시연 진입 (2026-10-16)

홈의 주 행동은 `합성 데이터 시연 시작`이다. 시연은 실제 계정 기록과 분리된 컨테이너의 시연 로그인으로 바로 진입하며, 측정 준비 시트나 두 번째 샘플 홈을 거치지 않는다. 프로필 → 골격근량 → 설정 → 안전 문진 → 시뮬레이션 흐름은 유지한다. 예약·출석과 실제 측정 기록은 보조 탐색으로 제공한다. 실제 FITRUS 원격 측정·실제 진동은 연결되지 않았음을 홈에 표시한다. 시연을 닫으면 진입한 원래 화면으로 돌아간다.

## 합성 시연의 중복 로그인 제거 (2026-10-17)

합성 시연 진입 화면은 참여자 코드·PIN·로그인 버튼을 제공하지 않는다. 시연 대상을 선택하고 `시연 시작`을 누르면 격리된 고정 샘플 세션으로 프로필 확인부터 진행한다. 합성 데이터임을 표시하며 실제 계정의 식별자·세션·측정값을 샘플 인증에 사용하지 않는다. 독립 Backend API 모드의 실제 참여자 코드·PIN 인증은 유지한다. 이전 화면으로 돌아가기는 시작 전에도 제공한다.
