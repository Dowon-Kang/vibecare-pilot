# VibeCare UX 진단·설계

> 아래 진단은 당시 앱 코드를 수정하지 않은 기록이다. 이후 사용자가 기록 이동 복구·출처/연구 등급 안내·결과 정보 순서 개선의 실제 구현을 승인했다. 후속 구현과 검증 증거는 문서 마지막 절에 별도로 기록한다.

> 2026-10-06 추가 승인: 사용자가 기존 Draft PR 반영·CI 실행에 이어 병합과 공개 GitHub Pages 배포까지 요청했다. 필수 4개 CI 검사와 main 재검사 성공을 조건으로 기존 배포 경로를 사용하며 보호 규칙을 유지한다. 배포 후 공개 웹의 샘플 결과→기록→복귀를 검증한다. 실제 장치 실행 금지와 기존 데이터·API 계약은 유지한다. 완료 증거는 PR과 Actions 실행에 기록한다.

## 2026-10-06 진단·설계 범위

목표는 처음 사용하는 고령 연구 참여자가 앱의 목적, 측정값의 의미와 한계, 다음 행동을 이해하도록 하는 것이다. 이번에는 앱 코드·테스트·알고리즘·API·안전 정책을 수정하지 않는다. 아래 안은 구현 제안이며 승인된 새 제품 요구사항이나 검증된 사용자 반응이 아니다. 기존 UX 문서가 있어 이 파일을 갱신했다.

- 대상: `Dowon-Kang/vibecare-pilot`. 분석 작업 트리 `E:\산학협력\vibecare-pages-update`, `handoff-verification-20261006`, HEAD `b4823a7ad27cba866ef03f7d35426b26bf901405`.
- 2026-10-06 fetch로 확인한 main: `69307b9015f420803a132048ee98031c322d3cc1`. 분석 HEAD와 main의 `mobile-app/lib` 차이는 없다.
- 공개 화면: [GitHub Pages](https://dowon-kang.github.io/vibecare-pilot/). 같은 main SHA의 [성공한 배포 실행](https://github.com/Dowon-Kang/vibecare-pilot/actions/runs/37194960896)을 확인했다. 배포 이력은 근거이며 브라우저가 받은 파일의 해시까지 대조한 것은 아니다.
- `VIBECARE_UIUX_WORK_ORDER.md`는 작업 트리, 영문 프로젝트 경로, 첨부 경로에서 발견하지 못했다. 이 요청의 조건을 적용했다.
- `project-industry`, `vibecare-norman-ux`의 원칙을 적용했다. 스킬의 영문 경로에는 더 오래된 `c800fb9`와 미커밋 UI 변경이 있어 이번 대상 GitHub 버전과 구분했다. 그 변경과 기존 미추적 `docs/architecture-map.md`는 보존했다.
- 읽은 근거: AGENTS, README, 제품·아키텍처·design·plan·checklist, 기존 UX/NFR 문서, 화면·테마·컨트롤러·환경/Provider·측정 저장소·등급/추천 계산·관련 테스트. 파일 위치와 줄 번호는 이 HEAD 기준이다.

### 증거의 구분

**관찰**은 실행한 웹 화면/AX 트리, **코드 사실**은 소스에서 확인한 동작, **추론**은 예상 사용자 영향이다. 사용자 인터뷰·실사용자 피드백은 수집하지 않았다. 확신도는 현상과 원인에 따로 적용하며, UX 효과는 사용자 과업 검사 전까지 가설이다.

### 먼저 고칠 3개

1. **U01 기록 진입 복구**: 결과의 근거를 확인하는 길이 실제로 막힌다. 기존 기능을 되살리는 작은 경로 작업으로 범위를 제한한다.
2. **U02+U04 의미·출처 정리**: 연구 등급/건강 상태/안전 자격의 구분과 합성/서버 문구를 일치시킨다. 숫자와 안전 정책을 바꾸지 않는다.
3. **U03 결과의 정보 위계 변경**: 전체 체성분 상태를 기존 상세로 옮기고 비교와 다음 행동을 앞에 둔다. U01이 해결돼 상세 접근성이 확보된 뒤 적용한다.

U11/U14는 다음 수직 흐름의 접근성·안전 이해 필수 검증에 포함한다. 우선순위가 낮다는 뜻으로 안전 차단을 완화하거나 보조 기술 검사를 생략하지 않는다.

## 첫 설계 대상: 결과 화면

요청한 **내 상태 요약 → 의미와 한계 → 이전 기록 비교 → 다음 행동 → 상세 보기** 순서를 채택할 만하다. 단, “내 상태”를 건강 종합 판정으로 만들지 않고 **이번 측정 요약**으로 정의한다. 현재 증상 차단/데이터 오류가 있으면 오류·차단 안내를 요약보다 먼저 보여주는 예외가 필요하다. 고정 CTA는 화면 아래에 계속 보이며 문서 순서는 읽기 순서이다.

### 최소 구성안 (구현 전 제안)

```text
[뒤로] 측정 결과                         [메뉴]
샘플 합성 데이터 · 실제 장치 미연결

이번 측정의 골격근량
12.5 kg       측정 시각 / 출처
연구용 설정 분류: 낮음

이 값은 몸의 골격근량을 나타냅니다.
키로 보정한 지수로 연구 설정을 분류합니다.
건강 진단이나 실제 장치 사용 허가가 아닙니다.

직전 기록과 비교
직전 시각 12.4 kg → 이번 시각 12.5 kg
차이 +0.1 kg · 변화가 효과를 뜻하지 않습니다.
[최근 4회 변화 보기]

다음: 부위별 시뮬레이션 설정과 안전 문진 확인
[전체 측정 항목]  [연구 기준과 계산 근거]

하단 고정: [부위별 설정 확인]
```

위 숫자는 관찰한 합성 예시이며 사용자 결과를 하드코딩하지 않는다. 측정 시각을 동기화 시각과 혼용하지 않는다. 결과 등급은 **최신** 골격근량/키²의 현재 규칙을 유지한다. 최근4회 평균·SD/CV·원본은 기존 기록/근거에서 그대로 확인하고 최신 결과를 평균 결과로 바꾸지 않는다. 전체10항목·생체신호·정의/방법/프로토콜·규칙 버전은 삭제하지 않고 상세에 보존한다. 긴 영문 상태 코드는 연구 상세에 두고 주요 화면의 회복 행동은 한국어로 설명한다.

### 표시 상태와 다음 행동

| 상태 | 요약/한계·비교 | 다음 행동·보존 제약 |
|---|---|---|
| 합성 정상 데이터·문진 전 | 합성 예시, 최신/직전 차이, 연구 분류. 안전 확인 전임을 표시 | 설정 확인으로 이동 가능. 시연 허가는 기존 문진/서버 규칙을 통과한 뒤에만 요청 |

### 시각·접근성 설계 기준

- 기존 teal/neutral Theme와 버튼 모양을 유지한다. 핵심 숫자32–40, 제목22, 설명 본문17을 시작점으로 하되 모든 텍스트 확대를 허용한다. 수치/단위는 함께 읽히도록 한다.
- 바깥 여백16–24, 항목 사이12–16, 섹션 사이24를 기존 토큰으로 구성한다. 카드 안에 카드가 반복되는 구조를 줄이고 제목과 읽기 순서로 위계를 만든다.
- 결과의 teal은 선택/행동을 표시한다. 증가=건강 개선, 낮음=위험이라는 색 체계를 추가하지 않는다. 단위·변화·상태는 문구/아이콘으로도 전달한다.
- 본문/상태 일반 텍스트 대비4.5:1, 큰 텍스트3:1을 목표로 실제 배경/alpha를 검사한다. [WCAG 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [200% 텍스트 확대](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html), [Android 48dp 목표](https://support.google.com/accessibility/android/answer/7101858?hl=en)를 2026-10-06 확인했다. 이 문서는 앱 전체의 준수 인증이 아니다.
- 모든 행동48dp 이상, 안전 문진도 동일 기준. 포커스/선택/비활성/진행 중을 구분하고 사유는 CTA 근처에 둔다. 스크린리더는 “질문·답·선택 상태”와 “측정 시각·값·단위·차이”를 읽을 수 있어야 한다.
- 320px/200%에서는 줄바꿈·세로 배치를 허용한다. 고정 CTA가 본문·키보드·설문 응답을 가리지 않아야 한다. 넓은 화면은 기존 PageContent와 같은 제한 폭을 이용하고 중앙의 좁은 작업면으로 유지한다.
