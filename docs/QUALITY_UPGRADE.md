# VibeCare 품질 개선 — 2026-09-07

사용자가 승인한 입력 검증 → 계산·출력 일치 → 실행 안전 → Android 첫 화면 개선을 반영했다. 실제 공급사 API 호출이나 물리 장치 작동을 검증한 결과는 아니다.

## API 주소를 쉽게 읽는 법

`VIBECARE_API_BASE_URL`은 앱이 접속할 우리 서버의 공통 주소다. 빈 값이면 샘플 시연이다. 아래 경로가 그 주소 뒤에 붙는다.

| 경로 | 뜻 | 입력 → 출력 |
|---|---|---|
| GET /health | 서버 응답 확인 | 없음 → 상태. 물리 장치 연결 확인은 아니다. |
| POST /v1/auth/pin | 로그인 | 참여자 코드·PIN → 참여자 정보·로그인 토큰 |
| POST /v1/auth/refresh | 로그인 연장 | 갱신 토큰 → 새 접근 토큰. 앱에서 401이면 한 번만 자동 재시도한다. |
| GET /v1/participants/me/measurement-set/current | 계산에 쓸 측정값 조회 | 측정 기기 ID → 이 참여자의 원본 목록·선택된 최근 유효 4건 ID |
| GET /v1/participants/me/vitals | 생체신호 조회 | 로그인 참여자 → 혈압·심박 등 표시용 데이터 |
| GET /v1/algorithm-rules/current | 계산 규칙 조회 | 없음 → 현재 활성화된 유효 규칙. 없으면 실행 불가 |
| POST /v1/recommendations/authorize | 실행 전 서버 검증 | 측정 ID 4개·안전 답변·규칙 버전·강도·측정/출력 기기 ID → 60초짜리 실행 허가 또는 거절 |
| POST /v1/device-sessions | 시연 시작 | 허가 ID·대상 기기 ID·중복 방지 키 → 세션 ID·시연 상태·명령 JSON |
| POST /v1/device-sessions/{id}/stop | 시연 중지 | 세션 ID·중지 이유 → STOPPED/COMPLETED 확인 |
| POST /v1/device-sessions/{id}/events | 시연 이벤트 기록 | 이벤트 → 수신 확인. 완료 후 다시 실행 상태로 바꾸지 않는다. |
| POST /v1/session-feedback | 사용 후 피드백 저장 | 세션 ID·운동 자각도·통증·어지럼 등 → 저장 결과. 현재 앱 입력 화면은 미구현 |
| POST /v1/fitrus/measurements/{kind} | 공급사 API 중계 | 기기 ID·공급사 요청 본문 → 원본 응답 보관. 표준 측정값 변환은 미구현 |

공급사 공통 주소는 `https://api.thefitrus.com/fitrus-ml/measure`다. 뒤에 `/bodyfat`(체성분), `/bp`(혈압), `/hr`(심박), `/stress`, `/stress2`(스트레스), `/bodytemp`(온도)가 붙는다. 이는 코드에 설정된 경로의 설명이며 실제 성공 응답을 확인했다는 뜻은 아니다. 공급사 키는 서버에만 둔다.

`sourceDeviceId`는 측정한 BIA 기기, `deviceId`는 명령을 받을 시연 기기다. 서로 구분했다. 예전 호출과의 호환을 위해 sourceDeviceId 생략 시 deviceId를 측정 기기로도 해석하지만 신규 앱은 둘 다 보낸다.

## 계산과 명령의 의미

현재 공식은 연구용 규칙 `pilot-0.3.0`이다. 샘플 여성 72세의 경우 기본 50% × 나이 0.9 × 여성 0.95 × 체지방 범위 밖 0.9 = 38.475 → 반올림 38%다. 시간 300초, 주파수 20Hz다. 평균 BMI가 18.5 미만이면 계산값을 보여주더라도 실행은 보류한다.

다섯 필수값은 체중·BMI·체지방률·체지방량·골격근량이다. 나머지 7개 표시값이 없으면 null이며 필수값이 있는 측정을 무조건 버리지 않는다. 숫자 아닌 값·0 이하·중복 ID·다른 참여자/기기 혼합·불일치를 검사한다. 체지방 일치 오차 1%p, BMI 오차 0.6은 기존 앱 검사를 서버로 맞춘 기준이며 임상적으로 검증된 허용 오차라는 뜻은 아니다.

명령 JSON은 앱 내부 전송 계약이다. 강도 38%는 실제 가속도 g, 진폭 mm, 모터 PWM이 아니다. 최종 장치 규격이 정해지면 별도 변환과 출력 교정이 필요하다. 소수 주파수를 임의로 반올림하지 않도록 현재 계약은 정수 Hz로 맞췄다.

## 서버에서 막은 문제

- 같은 중복 방지 키를 다른 참여자나 다른 요청이 사용하면 409로 거절한다.
- 하나의 대상 기기에 진행 중 세션이 있으면 DB 트리거로 두 번째 실행을 차단한다. 실패하면 실행 허가 소비도 롤백한다.
- 비활성·깨진 규칙을 기본 규칙으로 대체하지 않는다. 허가 후 규칙이 비활성화되거나 버전이 바뀌어도 시작을 차단한다.
- 최근 불량 측정 20건 때문에 그보다 오래된 유효 4건이 사라지던 조회 문제를 해결했다.
- 완료를 DB에 기록하고 종료된 세션의 추가 이벤트를 거절한다.
- 앱은 HTTP 성공만으로 중지됐다고 판단하지 않고 종료 상태 응답을 확인한다.

## 적용과 남은 작업

서버 배포 시 `services/api/migrations/0003_session_safety.sql`을 대상 D1 DB에 적용해야 장치 중복 실행 방지가 작동한다. 이 작업에서는 운영 DB 변경이나 배포를 하지 않았다. 새로 추가한 테스트는 임시 메모리 SQLite에 실제 세 개 마이그레이션을 적용한다.

남은 실제 연동 작업:

1. FITRUS 성공/오류 응답 샘플과 필드·단위를 확인하고 원본 응답 → 표준 측정값 변환을 구현한다.
2. 물리 장치의 통신 규격, ACK, 출력 범위·교정, 긴급 중지를 확정한다. 지금은 실제 모드를 서버에서 차단한다.
3. 실제 운영 전에는 앱 재시작·강제 종료 후 세션 복원, 서버/기기 watchdog, 대상 기기 등록·접근 통제, 규칙 버전 불변 관리가 필요하다. 현재 시연을 실제 장치 운용에 그대로 쓰면 안 된다.
4. 계산 계수의 의학적 타당성은 별도의 연구·전문가 검토 대상이다. 테스트 통과는 구현 일치를 뜻한다.

기존 `docs/project-analysis`는 개선 전 인수 분석 기록이다. 현재 변경 사항은 이 문서를 기준으로 읽는다.
