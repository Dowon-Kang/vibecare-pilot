# 프로젝트 개요와 범위

## 정의·배경

| 항목 | 분석 | 근거/분류 |
|---|---|---|
| 이름 | VibeCare Pilot, 패키지 vibecare-pilot-web / vibecare_pilot / vibecare-worker | [사실] 각 package.json, pubspec.yaml, README |
| 문제 | 참여자가 어떤 측정·보정으로 어떤 진동 설정을 적용하는지, 오늘 실행해도 되는 상태인지 이해하기 어려움 | [사실] design.md §1~2에 명시된 개발 목적 |
| 주요 사용자 | 고령 연구 참여자와 현장 보조 담당자 | [사실] design.md |
| 사용자 가치 | 측정 원본·평균·계수·결과를 연결하고 위험 응답 또는 데이터 이상에서 실행을 차단 | [사실] UI·알고리즘 존재. 차단 완전성은 부분 구현 |
| 기존 방식 | 사람이 측정·연령·성별 등을 보고 설정을 조절했을 가능성 | [추론] 보정식 자동화 목적에서 추론. 실제 과거 업무·시간·오류율 기록 없음 |
| 해결 범위 밖 | 근감소증 진단, 검증된 의료 처방, 자동 학습, 실물 장치 자체의 안전 제어 | [사실] 해당 코드 없음; 기존 문서도 파일럿 계수를 임상 확정값과 구분 |

[사실] `plan.md`는 React PWA를 기준 화면으로 보존하고 Android 우선 Flutter로 주 클라이언트를 전환한다고 명시한다. `../vibration-design-report/src/content/report/ReportContent.jsx`는 연구자·안전 검토자·알고리즘 관리자 등 더 넓은 역할과 물리 상한·사후평가를 제안하지만, 실제 앱에는 참여자 로그인 한 종류만 있다.

[확인 필요] 실제 발주서·납품 계약·인체 적용 승인·고객 승인 수용 기준은 저장소에서 확인하지 못했다. 상위 연구자료 제목만으로 확정 요구사항을 만들지 않았다.

## 사용자 역할

| 역할 | 목적·주요 흐름 | 기능·권한 | 현 상태 |
|---|---|---|---|
| 참여자 | 코드/PIN→측정 확인→문진→추천→전송→시작→중지 | Worker Bearer sub에 해당하는 본인 데이터 | [사실] Mock UI와 서버 경로 구현, 일부 보안 결함 |
| 현장 보조자 | 참여자의 입력·상태 확인 보조 | 별도 보조자 계정·대리 권한 없음 | [추론] 같은 참여자 UI 사용 가능하나 책임·감사 주체 확인 필요 |
| 연구자·안전 검토자 | 규칙 검토·피드백·안전 승인 | 전용 화면/RBAC 없음 | [사실] 문서상 역할, 미구현 |
| 운영자 | D1·secret·빌드·릴리스 관리 | Cloudflare/개발 환경 권한 필요 | [사실] CLI 중심 설정만 있음; 누가 보유하는지 확인 필요 |
| 웹 데모 방문자 | 프로필·문진을 바꿔 추천식 이해 | 로그인 없음, 고정 Mock 데이터만 처리 | [사실] app/page.tsx |

## 범위 분류

| 구분 | 내용 |
|---|---|
| 구현 완료(한정) | [사실] Mock 로그인/측정 표시, 평균·파일럿 수식, 수동 강도 하향, Mock 전송·시작·중지의 기존 테스트 통과 범위 |
| 부분 구현 | [사실] 인증·토큰 생명주기, 안전 문진, 최신4건 선택, 서버 재계산, 실행허가, 세션 감사로그, 계약 문서 |
| 코드만 존재하고 운영 검증되지 않음 | [사실] Worker 실 HTTP 연결용 Repository, FITRUS 프록시, 이벤트·피드백 API, D1 배포 구성. 일부는 이번 메모리 어댑터 검사만 수행 |
| 미구현 | [사실] FITRUS 정규화·BIA/vitals ingest, 참여자 발급/수정, 앱 피드백, 자동 refresh, 실기기 REST/BLE·ACK watchdog·교정, CI·운영 롤백 |
| 향후 확장 예정으로 추정 | [추론] 변동성 분석, 반복측정 기반 계수 갱신, 안전 담당자 승인 화면. plan.md와 보고서에 근거한 계획이며 승인 일정 없음 |
| 현재 범위에서 제외 | [사실] 웹에서 실제 명령 전송; 학습/LLM 호출. [확인 필요] iOS·웹 Flutter·다기관 운영은 목표 여부 불명 |
