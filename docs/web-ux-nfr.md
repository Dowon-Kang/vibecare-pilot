# 웹 홈·예약 화면 비기능 요구사항 점검 (2026-10-03)

## 화면과 접근성

| 요구사항 | 확인 결과 | 근거와 범위 |
| --- | --- | --- |
| 넓은 웹 화면에서 본문이 과도하게 늘어나지 않는다 | PASS | 홈과 예약 화면의 본문 최대 폭을 800px로 제한하고 좌우 24px, 하단 48px 여백을 적용했다. 예약 화면 1200px 위젯 테스트에서 본문 폭과 카드 간격을 확인했다. |
| 작은 화면과 큰 글자에서 주요 동작을 사용할 수 있다 | PASS (위젯 테스트) | 홈과 예약 화면을 폭 320px, 글자 배율 2배에서 검사했다. 실제 모바일 브라우저 사용성은 별도 확인이 필요하다. |
| 출석 달력 상태를 색상 없이 이해할 수 있다 | PARTIAL | 날짜마다 출석 완료·미참여·예약됨·예약 없음의 스크린리더 레이블을 추가하고 이전 달·다음 달 버튼에 툴팁을 넣었다. 실제 스크린리더와 키보드 탐색은 NOT RUN이다. |
| 오류를 알아채고 회복할 수 있다 | PARTIAL | 샘플 홈에서 예약 로딩 실패를 숨기지 않고 오류 문구와 다시 시도 버튼을 표시한다. 네트워크 장애·느린 연결의 실제 브라우저 검증은 NOT RUN이다. |

## 알림과 신뢰성

| 요구사항 | 확인 결과 | 근거와 범위 |
| --- | --- | --- |
| 웹 홈을 열어 둔 동안 예약 시각 알림을 확인한다 | PASS (위젯 테스트) | 샘플 홈은 20초 간격으로 예약 시각을 확인하고 복귀·재로딩 후에도 확인한다. 동일 예약은 현재 화면 세션에서 한 번만 표시한다. 로그인 홈의 기존 주기 확인 기능은 유지했다. |
| 웹 페이지를 닫아도 알림을 받는다 | NOT IMPLEMENTED | Web Push와 서비스 워커 기반 전달이 없다. 사용자가 페이지를 열어 둔 상태에서만 화면 알림을 받을 수 있다. |
| 인증·데이터 격리 | PARTIAL | Supabase Auth와 예약 RLS를 사용한다. 서로 다른 두 실계정의 격리 및 운영 환경 보안 점검은 NOT RUN이다. |
| 실제 기기·보조 기술 검증 | NOT RUN | Android 알림 권한과 기기 예약 전달, 실제 스크린리더, 키보드 전체 탐색은 검증하지 않았다. |

이 표의 PASS는 자동화 테스트가 확인한 범위에만 해당한다. 알림 세부 조건은 [예약 알림 동작과 비기능 요구](notification-nfr.md)를 따른다.
