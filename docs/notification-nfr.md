# 예약 알림 동작과 비기능 점검 (2026-10-02)

## 동작 계약

- 사용자는 현재보다 늦은 시각을 예약하고, 1·4·12·52주 반복을 선택한다.
- 웹은 로그인한 사용자의 예약을 Supabase에서 읽는다. 페이지가 열려 있으면 20초마다 확인하고, 예약 시각이 지난 오늘의 미출석 예약을 화면 메시지로 한 번 안내한다. 타이머가 지연되어도 당일에는 안내한다.
- 웹 페이지를 닫으면 알림을 보낼 수 없다. 브라우저 푸시, 이메일, SMS는 구현되어 있지 않다.
- Android는 예약마다 기기 `AlarmManager`에 등록한다. 알림 권한이 없으면 사용자에게 권한을 요청한다.
- 출석이 저장되면 해당 Android 예약 알람을 취소한다. 출석 자체는 현장 방문 인증이 아니다.

## 비기능 점검

| 항목 | 상태 | 근거와 한계 |
| --- | --- | --- |
| 미래 시각 예약 알림 | PASS (단위 테스트) | 예약 전에는 안내하지 않고, 시작 5분 뒤에도 당일이면 한 번 안내한다. |
| 중복 방지 | PARTIAL | 앱 실행 중 예약 ID별 한 번 안내한다. 페이지를 새로고침하면 같은 날 재안내될 수 있다. |
| 웹 전달 지연 | PARTIAL | 활성 페이지에서 20초 주기로 확인한다. 브라우저가 탭을 중지하면 지연될 수 있고, 당일 재개 시 보충 안내한다. 전달 시각 보장은 없다. |
| 웹 백그라운드 전달 | NOT IMPLEMENTED | 닫힌 페이지에는 푸시가 없다. 서버 측 예약 작업과 Web Push 등록이 필요하다. |
| Android 전달 | NOT RUN | 코드와 빌드로만 확인했다. 실제 기기의 권한 거부·절전·재부팅 후 동작은 검증되지 않았다. |
| 계정별 데이터 보호 | PARTIAL | Supabase Auth와 `visit_bookings` RLS를 사용한다. 실제 계정 두 개로 격리 재검증이 필요하다. |
| 접근성 | NOT RUN | 실제 화면 읽기 도구와 키보드만 사용한 알림 확인이 필요하다. |
| 부하·장애 회복 | NOT RUN | 대량 예약, 느린 네트워크, 오프라인 복귀에 대한 실측이 없다. |

이 문서의 PASS는 명시한 테스트 범위에만 해당한다. 웹 푸시와 Android 실기기 전달을 운영 보장으로 해석하지 않는다.
