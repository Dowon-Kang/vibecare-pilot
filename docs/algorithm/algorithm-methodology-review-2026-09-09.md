# 근육량 기반 전신진동 알고리즘 냉정 평가와 재설계

> 후속 보강: [REQ-ALGO-05 / adaptive0.2·readiness0.8.1](adaptive-research-v2.md). 아래 초기0.1/0.8 구현 기록 중 이력 처리·전이·프로토콜 선택 설명은 후속 문서와 코드를 우선한다.

검토일: 2026-09-09
요구사항: REQ-ALGO-03
대상: 발판형 전신진동(WBV) 장치, 고령자, FITRUS 체성분 API
결론 상태: 연구용 설계. 임상 처방·실기기 자동 실행 승인 아님.

## 1. 한 줄 결론

현재 코드는 **동일 입력을 같은 결과로 계산하는 규칙 엔진**으로는 잘 만들었지만, **근육량이나 체지방으로 사람별 안전한 진동 용량을 결정하는 임상 알고리즘**으로는 아직 성립하지 않는다. 이번 재설계는 임의 용량식을 더하지 않고, `측정 정의 → 데이터 품질 → 근육 평가 → 승인된 연구 프로토콜 → 실제 물리량 → 장치 교정 → 독립 검토`가 모두 확인되어야 다음 단계로 갈 수 있는 실패 폐쇄형 연구 게이트를 만든다.

## 2. 조사 방법

- 검색일: 2026-09-09
- 검색 흐름: WBV 용량·고령자 효과, 비만/체지방, 근감소증/근육량, 물리량·전달률·안전, BIA 반복성, 의료 소프트웨어 임상평가의 4개 작업축
- 12개 검색식에서 상위 10건씩 총 120개 검색 결과를 1차 선별하고, 체계적 문헌고찰·국제 합의문·원 연구·공식 규제 문서를 우선 정독했다.
- GitHub 구현은 임상 수치의 근거로 쓰지 않았다. 규칙 버전, JSON 계약, 이유 코드, 재현 가능한 fixture 구조만 참고했다.
- 사실, 추론, 연구가설을 다음처럼 구분한다.
  - `EVIDENCE`: 원문이 직접 지지하는 사실
  - `INDIRECT`: 다른 장치·집단·측정 정의에서 가져온 간접 근거
  - `PILOT`: 연구팀이 검증해야 하는 가설 또는 공학 기준
  - `ABSENT`: 현재 검증 자료가 없음

|---|---:|---|

| 근육량→진동 용량 인과 | 1 | LOW/MIDDLE/REFERENCE를 12/16/20Hz·30/40/50%에 연결하는 직접 근거가 없다. |

| 물리적 용량 정의 | 1 | 주파수는 있으나 `%`와 진폭·가속도 관계가 없고, 파형·자세·전달률·부하 조건이 실행값에 포함되지 않는다. |
| 안전·임상 검증 | 1 | 통증·어지럼·보류 차단은 있으나 금기·낙상·심혈관 위험·유해사건·전향 검증이 부족하다. |
| 실패 폐쇄 | 4 | 현재 연구 모듈은 `command=null`, `realDeviceSendAllowed=false`를 유지한다. 이 경계는 반드시 보존한다. |
| 앱/API/실장치 통합 | 1 | 새 연구 모듈은 UI, FITRUS 성공 응답 Adapter, 물리 장치와 연결되지 않았다. |

총평: **소프트웨어 프로토타입은 양호, 임상 용량 알고리즘은 미성립**이다. 발표나 문서에서는 “근육량 기반 시뮬레이션 규칙”이라고 해야 하며 “개인 맞춤 안전 처방”이라고 말하면 안 된다.

## 4. 기존 방식에서 폐기하거나 격리할 것

1. `체지방이 높음 → 시간·% 증가`는 실행 규칙에서 제거한다. 체지방은 이후 반응 차이를 검증할 공변량이다.
2. 체지방 LOW/MEDIUM/HIGH 사이 선형보간은 허위 정밀도를 만든다. `user-region-fat-0.2.0`은 사용자 표 재현 fixture로만 보존한다.
3. 발판형 WBV에서 어깨·팔·복부를 독립 부위로 골라 Hz를 지정하는 표는 전달 메커니즘이 확인되지 않았다. 별도 국소 장치처럼 표현하지 않는다.
4. UI의 `강도 %`는 물리적 용량이 아니다. 장치 모델·펌웨어·하중별 `peak-to-peak displacement(mm)`와 `peak/RMS acceleration(g)` 교정표가 생기기 전에는 출력값으로 사용하지 않는다.
5. 30분·99% 같은 값은 연속 노출인지, 휴식을 포함한 총 세션인지조차 정의되지 않았다. 승인된 운동/휴식 bout 구조로 바뀌기 전 인체 적용값으로 사용하지 않는다.
6. `status=READY`이면서 `executionStatus=CALIBRATION_REQUIRED`인 이중 의미를 폐기한다. 평가 상태와 실행 허가는 별도 타입으로 둔다.

|---|---|
| 의미 우선 | 공급사 필드명이 아니라 측정 정의(ASM/SMM), 방법(BIA/DXA), 단위, 장치 검증 문서를 확인한다. |
| 인과와 상관 분리 | 근육량은 위험 층화 근거로 쓰되, 특정 용량의 원인이라고 가정하지 않는다. |
| 물리 단위 우선 | Hz와 UI `%`가 아니라 변위·가속도·파형·자세·bout·휴식까지 프로토콜로 묶는다. |
| 실패 폐쇄 | 정의, 승인, 교정, 안전 문진 중 하나라도 빠지면 명령을 만들지 않는다. |
| 거짓 정밀도 금지 | 근거 없는 연속 보간·소수점 개인화·자동 증량을 하지 않는다. |
| 책임 분리 | 측정 평가, 프로토콜 선정, 교정 확인, 서버 실행 허가, 장치 제어를 다른 컴포넌트로 둔다. |
| 추적 가능성 | 규칙 버전, 문헌/승인 ID, 입력 스냅샷, 장치 교정 ID, 이유 코드를 결과에 남긴다. |
| 검증 수준 분리 | 코드 계산 정확성, 장치 출력 정확성, 사람에게 의미 있는 효과를 각각 별도로 검증한다. |
| 제한된 적응 | 피드백은 처음에는 수집만 한다. 승인된 후보 프로토콜 안에서 전향 검증된 모델만 다음 단계 선택에 쓴다. |
| 독립 검토 | 개발자가 통과시킨 테스트만으로 인체 적용하지 않고 임상·장치 담당자가 별도 승인한다. |

## 6. 새 알고리즘 구조

```text
FITRUS 원본
  → 공급사 Adapter와 측정 정의 확인
  → 동일 참여자·동일 BIA 기기·표준화 조건의 유효 4건
  → 평균·표본 SD·CV·개별 경계 안정성
  → 검증된 정의일 때만 SMMI/ASMI 계산과 근육 층화
  → 계산된 층과 일치하는 연구 프로토콜 후보 검색
  → 승인 ID가 있는 후보만 선택
  → Hz·변위·파형·자세·bout·휴식으로 물리 프로토콜 평가
  → 실제 WBV 장치 교정 결과와 비교
  → 통증·어지럼·전문가 보류 및 별도 안전 절차
  → 독립 검토
  → 별도 서버 실행 허가(현재 미구현)
```

이번에 추가한 `research-gate-0.8.0`은 위 단계 중 근육 평가부터 독립 검토 직전까지를 순수 함수로 평가한다. 프로토콜 숫자를 코드에 발명하지 않고, 연구책임자가 승인한 catalog 중 **계산된 근육 층과 정확히 일치하는 후보가 하나일 때만** 선택한다. 후보가 없거나 둘 이상이면 중단한다.

### 상태 머신

```text
SAFETY_BLOCKED
DATA_REVIEW
PROTOCOL_REQUIRED
PROTOCOL_REVIEW
APPROVAL_REQUIRED
CALIBRATION_REQUIRED
CALIBRATION_REVIEW
INDEPENDENT_REVIEW_REQUIRED
```

마지막 상태도 장치 실행 허가가 아니다. 모든 상태에서 `command=null`, `realDeviceSendAllowed=false`다. 실제 명령은 향후 서버의 서명된 일회용 허가 계층에서만 만들 수 있다.

## 7. 현재 사용할 수 있는 수식과 사용할 수 없는 수식

### 사용 가능: 측정 요약

```text
meanMass = (m1 + m2 + m3 + m4) / 4
sampleSD = sqrt(Σ(mi - meanMass)² / 3)
CV(%) = sampleSD / meanMass × 100
SMMI = meanSMM(kg) / height(m)²
```

4건 평균은 프로젝트의 측정 노이즈 완화 규칙이지 임상 표준이라고 주장하지 않는다. BIA는 수분, 음식, 운동, 자세, 피부온도 등에 영향을 받을 수 있으므로 `표준화 측정 protocolRef`가 없으면 계산을 보류한다.

### 사용 가능: 정현파 후보의 이론 가속도

```text
Apeak(m) = peakToPeakDisplacement(mm) / 2 / 1000
aPeak(g) = (2πf)² × Apeak / 9.80665
```

이 수식은 정현파의 기계학 관계다. 실제 장치의 파형과 하중에서 가속도계로 측정한 값과 비교해야 하며, 사람 몸에 전달되는 값은 자세와 접촉 조건 때문에 플랫폼 값과 같지 않을 수 있다.

### 현재 사용 금지

```text
진동강도 = 기본강도 × 나이계수 × 성별계수 × 체지방계수
체지방이 높을수록 시간/강도 증가
근육등급 LOW/MIDDLE/HIGH → 고정 12/16/20Hz 처방
UI 90% = 사람에게 전달된 물리 용량 90%
```

이 식들은 코딩은 가능하지만 출력과 안전·효과 사이의 유효한 임상 연관이 입증되지 않았다.

## 8. 근육량 중심 개인화의 올바른 발전 경로

### 지금: 설명 가능한 결정 규칙

- 근육량/키²는 검증된 측정 정의가 있을 때만 층화한다.
- 층은 연구 모집단 분류와 protocol catalog 선택 키다.
- 용량은 연구자가 미리 승인한 제한된 후보 집합에서만 온다.
- 체지방, 나이, 성별은 자동 승수가 아니라 분석 변수로 저장한다.
- 직전 세션의 RPE, 통증, 어지럼, 중단 여부도 저장만 하고 자동 증량하지 않는다.

### 데이터가 쌓인 뒤: 반복측정 반응 모델

한 사람에게 여러 세션이 생기므로 단순 선형회귀보다 참여자별 차이를 분리할 수 있는 혼합효과 모델을 1차 기준 모델로 둔다.

```text
logit P(adverseEvent=1)
 = β0 + β1·SMMI_z + β2·age_z + β3·bodyFat_z
   + β4·measuredPeakAccelerationG + β5·activeDuration
   + β6·posture + β7·sessionNumber + participantRandomIntercept
```

RPE가 순서형이면 ordinal mixed model, 기능 변화가 연속형이면 linear mixed model을 별도로 쓴다. 모델은 임의의 Hz를 생성하지 않고 승인된 후보 각각의 위험·기대효과를 비교한다.

```text
선택 = argmax(기대효과 - λ × 유해사건위험)
제약: 후보가 연구승인·장치교정 범위 안이고 위험확률이 사전 승인 임계값 이하
```

`λ`와 위험 임계값은 코드 작성자가 정하지 않는다. 임상 연구계획서와 안전성 검토에서 사전 등록한다. 데이터가 작을 때 복잡한 딥러닝을 쓰지 않는다. 먼저 해석 가능한 혼합효과/베이지안 계층모델을 기준으로 두고, 참여자 단위 분할과 전향 검증으로 성능을 확인한다.

### 구현한 적응형 연구 선택기 — adaptive-research-0.1.0

임상 모델을 학습할 데이터가 아직 없으므로 머신러닝을 가장하지 않고, 연구책임자가 승인한 정책을 해석하는 결정론적 상태 머신을 구현한다.

```text
근육 층 LOW / NOT_LOW / MIDDLE / REFERENCE
  → 승인 policy의 initialStageByCategory에서 시작 stage 선택
  → 세션 완료·RPE·통증·어지럼·보류·시간/Hz/강도 체감 확인
  → HOLD / KEEP / STEP_DOWN / STEP_UP_REVIEW 중 하나 결정
  → 선택된 stage의 protocolId를 research-gate-0.8.0에 전달
  → 물리 프로토콜·장치 교정·독립 검토
```

전이 규칙은 다음과 같다.

| 조건 | 결정 |
|---|---|
| 현재 또는 직전 세션 통증·어지럼·보류 | `HOLD`, 후보 없음 |
| 직전 세션 미완료 | `HOLD`, 후보 없음 |
| `STRONG` 응답 하나 이상 또는 RPE 상한 초과 | 승인된 바로 아래 stage 후보. 이미 최저면 `HOLD` |
| 같은 stage에서 정책이 요구한 횟수만큼 완료, RPE 목표범위, 세 항목 모두 반복 `WEAK` | 승인된 바로 위 stage를 `STEP_UP_REVIEW`로 제안 |
| 응답 혼합, 횟수 부족, 적절 응답 | 현재 stage 유지 |
| 이미 최고 stage | 더 올리지 않고 유지 |

최소 반복횟수와 RPE 범위는 코드 상수가 아니라 `approvalRef`가 있는 policy 입력이다. stage도 `rank + protocolId`만 가지며 물리 수치는 별도 승인 catalog에 둔다. 따라서 같은 턴에 시간·Hz·변위를 제각각 올려 기계적 용량을 예측 불가능하게 만들지 않고, 한 번에 하나의 사전 검토된 stage만 이동한다. `STEP_UP_REVIEW`는 자동 승인되지 않으며 모든 상태에서 장치 명령은 null이다.

## 10. 검증 계획

### 분석/기술 검증

- 같은 입력의 TypeScript/Dart 전체 JSON 결과 일치
- 3건/5건, 혼합 사용자, 혼합 BIA 장치, 중복 ID, 결측, NaN/Infinity, 정의 미확인 차단
- SMMI 경계 바로 아래/같음/위와 표시 반올림 독립 검증
- 프로토콜 후보 없음/중복/근육 층 불일치 차단
- 승인 ID 없음, 장치 ID 불일치, 만료 교정, 계측 허용오차 초과 차단
- 주파수를 2배로 하면 동일 변위에서 이론 peak g가 4배가 되는 속성 테스트
- 모든 경로에서 command가 null이고 실장치 전송이 false인지 검사

### 임상 검증

- 주요 결과: 사전 정의된 기능 지표와 환자 관련 결과
- 안전 결과: 통증, 어지럼, 낙상/근접사고, 조기중단, 유해사건
- 알고리즘 지표: 유해사건 위험의 민감도·음성예측, calibration slope/intercept, Brier score와 신뢰구간
- 데이터 분할: 같은 참여자의 세션이 학습과 검증에 동시에 들어가지 않도록 participant-level split
- 비교: 전문가가 정한 고정 안전 프로토콜 또는 표준 운동 대조군
- 평가 순서: bench → 감독 feasibility → 전향 파일럿 → 외부 검증

정확도 하나로 완료 판정하지 않는다. 임상 검증은 코드 테스트로 대체할 수 없다.

## 13. 완료 정의

### 이번 REQ-ALGO-03 완료

- 기존 알고리즘의 과학·수학·공학·안전·통합 수준을 분리 평가했다.
- 잘못된 체지방 용량 인과와 UI `%`의 물리량 사용을 배제했다.
- 승인된 catalog만 근육 층으로 선택하는 `research-gate-0.8.0`을 TS/Dart로 구현했다.
- 장치 물리량과 교정·승인·독립 검토 게이트를 코드와 테스트에 포함했다.

### 실제 알고리즘 완료가 아닌 이유

- FITRUS 성공 응답과 골격근량 정의가 미확정이다.
- WBV 장치의 실제 주파수·변위·가속도·파형·하중 교정자료가 없다.
- 연구책임자가 승인한 근육 층별 protocol catalog가 없다.
- 대상 고령자에서 전향적 안전성·효과·개인화 모델 검증이 없다.

이 네 가지가 없으면 어떤 수식을 추가해도 “완성된 개인화 진동 알고리즘”이 아니라 숫자를 자동 생성하는 가설에 머문다.
